# atlas-gate

The pull-request gate for **public** members of the Bitspark constellation.

The constellation's members are libraries that consume each other by exact, content-pinned versions.
One rule keeps those builds sound, and every member must pass it before a change merges. It is
called **Gate A**:

- every direct dependency on a *type-identity-critical* component is pinned to an **exact** version,
  never a range;
- no such component resolves to **two versions** in one language's dependency graph.

A component is type-identity-critical when two copies of it in one build would produce incompatible
types. Private members run Gate A through the constellation's private governance tooling. A public
repository cannot reach that tooling, and should not need to, so this repository carries Gate A on its
own.

## What is here

| File | What it is |
|---|---|
| `gate.mjs` | Gate A. Zero-dependency Node.js; reads only the repository under test and `policy.json`. It never runs the repository's code, never reaches the network, and needs no token. |
| `policy.json` | The classification Gate A reads: for each catalog component, whether it is type-identity-critical and its Go module, Rust crate and npm package names; and the member names used to attribute dependencies. Nothing else. |
| `.github/workflows/gate.yml` | The required check, `substrate`, run on GitHub-hosted runners. |
| `test.mjs` | This distribution's own tests. |
| `PROVENANCE.json` | The commit of the governance repository this tree was generated from, and the SHA-256 of every file. |

## How a member is gated

An organization ruleset requires `.github/workflows/gate.yml` **at a specific commit of this
repository** on each public member. The workflow then runs in the member's context on every pull
request and merge-queue entry. It checks out the member's change, and this repository at the
workflow's own commit, so the checker that runs is the one the ruleset approved. A pull request
cannot replace it. The workflow fails closed: if it cannot identify its own commit, or the policy is
missing or empty, it reports an error rather than a pass that examined nothing.

To run it locally against a checkout:

```sh
node gate.mjs path/to/member
```

## Changes

Everything here is generated by `atlas gate export` in the constellation's governance repository,
from that repository's own Gate A source, and arrives as a pull request. Please don't edit it by
hand: a change belongs in the generator, so both gates stay identical.
